BACKGROUND (2026-10-22)
  Plex Media Server (systemd unit plexmediaserver on uba5) was found stopped today;
  Jay started it by hand (sudo systemctl start plexmediaserver). Overlord didn't
  report it: the systemd section lists only *failed* units, and a unit that was
  stopped cleanly, or never started at boot, isn't "failed". Nothing else looks at
  Plex. The OTA chain behind it:
    HDHomeRun Flex 4K tuner(s) -> hdhr-ac4 container (ghcr.io/johnb-7/hdhr-ac4:1.5,
    bridge network, host 8080 -> container 80, host 5004 -> 5004, restart
    unless-stopped, no compose project; converts AC-4 audio) -> Plex.
  Plex logs and URLs can carry X-Plex-Token values, a full-access Plex credential.
  Jay suspects Plex may be causing LAN problems and wants it watched for the next few
  days, so this ticket also collects Plex's network footprint (Stage 1 step 3).

STAGE 0: CHECKS AND WHY PLEX WAS DOWN (Claude Code, read only on uba5)
  1. systemctl is-enabled plexmediaserver; systemctl status plexmediaserver
     --no-pager (Active since). If it is disabled, it won't start after a reboot:
     say so and print the command for Jay (sudo systemctl enable plexmediaserver).
     Don't run it.
  2. Why it was down: journalctl -u plexmediaserver --since "14 days ago" --no-pager,
     filtered to start/stop/exit/fail lines, plus last boot times
     (journalctl --list-boots | tail -5). Answer: did it crash, get stopped, or never
     start after a boot? Run every line through redact.sh before showing it, and
     never quote a line containing "Token".
  3. curl -s -m 5 http://127.0.0.1:32400/identity (Plex's unauthenticated identity
     endpoint: version, machineIdentifier). Report whether it answers, and the version.
  4. The tuner(s): find the HDHomeRun address without guessing, e.g. from
     hdhr-ac4's configuration (docker inspect hdhr-ac4: Env and Cmd, redacted, names
     and IPs only), or hdhomerun_config discover if installed. Then
     curl -s -m 5 http://<tuner>/discover.json (model, firmware, TunerCount) and
     /status.json (per-tuner in use / idle). Report what answers. If no address can be
     found, ask Jay.
  5. hdhr-ac4: curl -s -m 5 -o /dev/null -w '%{http_code}' http://127.0.0.1:8080/ and
     the same for :5004/. Report codes only (which of them is a cheap health check).
  6. LAN footprint, read only: is vnstat installed and running (per-interface traffic
     history)? ss -tunp state established | grep -c plex (connection count);
     ip -s link for the main interface (errors, drops); whether Plex's DLNA server and
     GDM network discovery are on (Preferences.xml attributes DlnaEnabled and
     GdmEnabled only: read just those two names with grep, never print the file or
     any Token attribute). Report what you find.
  7. Ask Jay which other systemd services on uba5 must always be running (a starting
     list: plexmediaserver, docker, ssh, and anything Stage 0 finds enabled that looks
     like his: e.g. glances). STOP and report 1-6 before changing files.

STAGE 1: COLLECTOR
  1. systemd section: add "expected services" from a list at the top of uba5.sh
     (EXPECTED_UNITS="plexmediaserver docker ssh ..." from Stage 0 step 6). For each:
     name, is-active, is-enabled, active-since (ActiveEnterTimestamp), and NRestarts.
     Mark anything not active or not enabled with "EXPECTED BUT ..." so it stands out.
     Keep the failed-units and timers lists as they are.
  2. New section plex (after docker), each part failing on its own:
       - Plex: /identity answers? version.
       - Plex sessions are NOT collected (they need a token); no token is ever read
         from Plex's Preferences.xml or anywhere else.
       - hdhr-ac4: the HTTP codes from Stage 0 step 5 (its container state and
         error log lines already come from the docker section).
       - Tuner(s): from discover.json, ModelNumber, FirmwareVersion, TunerCount; from
         status.json, how many tuners are in use. UNREACHABLE if no answer in 5 s.
         The tuner address(es) go in a variable at the top of uba5.sh with a comment
         (no DHCP reservations yet, like cookie-cam's TODO "Harden device IPs").
     All through redact.sh like every section.
  3. Plex network footprint (in the plex section, for the "LAN issues" question):
       - established connections owned by Plex, by remote address count, local LAN vs
         outside (a count per group; no full address list for outside peers);
       - Plex's listening ports (ss -ltnup filtered to plex);
       - DlnaEnabled / GdmEnabled values (Stage 0 step 6 method);
       - the main interface's rx/tx errors and drops (ip -s link), and, if vnstat is
         installed, traffic per hour for the last 24 h (vnstat --json h, summarized to
         the top 5 hours). If vnstat isn't installed, say so in the section; installing
         it is Jay's call (sudo apt install vnstat), not this collector's.
       - the count of plexmediaserver journal lines at warning or worse in the last
         24 h, deduplicated top 10 (redacted).
  4. redact.sh: redact X-Plex-Token values in any form (query string
     X-Plex-Token=..., header X-Plex-Token: ..., JSON/XML attributes PlexOnlineToken=
     and authenticationToken=). Add samples to --selftest for each form, and a "keep"
     sample (e.g. the word "Token" in an ordinary log line) so it doesn't over-redact.
